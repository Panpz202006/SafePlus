# SafePlus 数据定义与评价协议 v2（建议冻结版）

## 0. 先定任务，不再用一套数字同时证明三件事

此阶段只研究**事后起点恢复**：给定账号截止第一次相关处置的历史 `x`、该次处置时点 `td`，预测公开可见证据范围内的首次违规位置 `tf_obs`。它不是在线早检。仍保留正常对照用于建模及未来误报评价，但本轮Exp05没有正常对照的推断风险输出。

## 1. 两个互相独立的标注维度

**真值精度（回答“从证据能精确到哪里”）**：

- `EXACT_PUBLIC`：能对齐到一次真实已发布修订ID和UTC时间。
- `EXACT_OTHER_LOG`：能找到可信公开日志的UTC，但不等于序列中某次已发布编辑；只计算UTC误差。
- `INTERVAL`：在已经证明的正常下界 `lower` 与首个已确认违规上界 `upper` 之间，即 `(lower, upper]`；不得强行拿 `upper` 当真值。
- `RIGHT_CENSORED`：已审窗口结束时未发现定义内违规；不是终身清白，不存在已知 `tf`。
- `LEFT_CENSORED`（下一批新增）：观察一开始就有违规，之前真实状态不可见；不得臆造正常前缀或绝对首次时刻。
- `UNKNOWN`：证据不足、不明确、事件用户身份或时间无法对应；只能审计，不进入数值起点测试。

**行为历史信息量（回答“模型看得到多少有用过程”）**：

- `PREFIX_1`：仅1次已确认正常前缀，仍可用于精确事件证据研究，但不足以证明长期正常后变化。
- `PREFIX_2`：2次正常前缀。
- `PREFIX_3PLUS`：至少3次已核验正常前缀，用于优先研究**行为变化**；无额外条件下不代表更真。
- 同时记录：实际发布编辑数、总观察天数、中位编辑间隔、正文可用性、主空间/非主空间比例、最后确认正常与首次确认违规间的未知事件数。

这是**两个轴**，不能把“起点精确”直接等同于“行为变化信息充分”。当前61 EXACT中仅11个至少3次正常前缀，不能倒推61个都足以训练复杂行为转变。

## 2. 统一的观察边界

- 业务 `td`：本Wiki数据目前定义为首次**相关封禁**，不是第一次发现；禁止写成 first detection without proxy qualifier。
- 事件序列：只能使用观察终点之前已存在的**所有允许来源事件**。当前8特征仅来自已发布修订，过滤拦截日志暂不作为行为特征；不能只输入人工挑选的“正常/违规证据修订”，否则泄漏标签。
- 序列步 `k`：真实已发布修订的位置；截止时点的状态快照不是一条编辑，也不计入 `N_published`。
- 时间 `t`：保留原生UTC；同一秒时间顺序未知时不可猜测。每个账号一个 `t_start` 和 `observation_end`，记录缺失/截断。
- 模型输入与 `gold_onset.csv`、AI判案理由、违规内容标签、封禁理由、举报信息隔离；如未来增加正文特征，只能从预测时刻可见的**原始编辑正文**计算，统一覆盖正常和违规账号。

## 3. 指标：按标签类型先分流，不能混成一个MAE

### 对精确已发布事件（仅当前TEST中的8条）

主评价：每个账号 `e_event=|k_hat-k_gold|`，同时报告 `Exact@0`（完全对）、`Within-1`（差≤1次发布编辑）、逐账号对比 SafePlus vs Behavior-only 和 Delay-only 的胜/负/平。

辅助尺度：`e_norm_event=|k_hat-k_gold|/(N_published-1)`，且报告 `N_published` 分层。它只消除长度量纲，不自动保证统计公平；短序列误差不稳定，绝不可单凭该比例判断模型好坏。

### 对精确UTC、但不一定是发布行为的事件（当前TEST中的9条）

`e_utc=|t_hat-t_gold|` 报中位数、均值和误差分布。辅助 `e_norm_time=e_utc/(t_end-t_start)`，仅在观察跨度正且有意义时使用。时间窗过长（几年无编辑）会使这个比值虚假地很小，因此不可独自充当主指标。

### 对区间 `(lower,upper]`（当前TEST中的29条）

`hit = (lower < t_hat <= upper)`；`distance = max(lower-t_hat,0,t_hat-upper)`。这是离区间距离，**不是精确起点的误差**。按区间跨度 `≤1天`、`1–7天`、`7–30天`、`>30天` 分层分别报告。宽区间更容易命中，决不能把四组混合命中率当成唯一表现。

以后如果保存完整 `p(tf | x,td)`，增加后验对区间赋予的概率质量（同样必须按区间宽度解释），以及可解释的概率校准；不要求周日前实施所有概率指标。

### 对右删失（当前TEST中的12条）

现有检测账号条件定位器没有提供其独立风险预测，输出 `NOT_DETECTED_UNSUPPORTED`。因此目前**不能**算“正常用户判对12/12”“假阳性率0”或AUC。将来要测正常误报，须先扩展前缀风险输出及生存/删失任务，再在盲测上固定阈值，不能在测试集选阈值。

## 4. 为什么始终要求同一账号做成对比较

对每个有可比真值的账号，先分别计算模型A/B的误差：`gain_i = error_baseline_i - error_safeplus_i`。大于0代表SafePlus赢该账号；等于0平局；小于0输。再汇总胜/负/平数量、典型误差（中位数）与置信区间。不要把有不同单位的EXACT误差和INTERVAL区间距离相加。

额外设置无学习基线：直接猜 `td` 附近、猜第一个编辑、猜中间编辑；使用与模型一样的观察信息、合法候选位置，避免不公平对照。**当前重评分文件只提供现有Behavior/Delay消融**，新基线应在VAL定规则后在新独立集合上报告。

## 5. 防数据泄漏及测试集冻结

当前已看过的原TEST 50个账号属于 `exploratory_test_20261024`，**不可通过重复调模型后继续宣称它是盲测**。对后续真实性能论文，必须保留新账号级、最好按身份关联组和来源独立的 `untouched_test_v2`。所有未来新阈值、模态和参数仅用TRAIN/VAL选择；输入处理只能使用推断时实际已可见事件。

## 6. 模型改动顺序（不轻易推翻原方法）

先完成**起点标注定义/分层和长度、时间索引、泄漏回归测试**；再将已发布修订的原始内容差异转成统一因果特征（如每次增删字数、外链新增数、跨命名空间变化、编辑摘要、删除比例）。当前8个特征是累计元数据，存在把自然时间进程误判为违规变化的风险，因此新内容特征实验必须与原8维版本单列，不可静默覆盖既有baseline。正文是否可用、违规标注、封禁理由不能成为作弊特征。

在未完成这些基本验证前，不要调 `w=2/3` 或 `T=1/3` 追分。当前 `T` 改变后验置信程度，对固定打分的argmax及顺序通常无效，不能把调T包装为定位改进。

## 7. 当前数据与真实研究声明的边界

保留200转变、100对照全部记录；输出中 `EXACT`/`INTERVAL`/`RIGHT_CENSORED`、`PREFIX_1/2/3PLUS` 必须同时能查询。论文正文应写“公开可见、独立核验范围内的违规行为起点”，而不是“一个人首次产生恶意意图的时刻”。原记录采用AI逐事件证据审核，未完成独立人工复核；暂称Silver/AI-audited，不自动称Gold。
