# BankSim 数据适配说明

## 用途

BankSim 是基于真实银行汇总统计构建的合成支付数据。本项目将其用于检查 SAFE、SAFE-R、SafePlus、RNN、LSTM 和 GRU 在另一类交易场景中的表现，而不是把 BankSim 的交易标签直接当作 SAFE 原始数据的等价物。

## 序列定义

- 实体：客户（`customer`）。
- 时间轴：原始 `step`，全数据为 0–179。
- 同一时间步聚合：交易笔数、金额总和/均值/最大值、唯一商户数，以及各交易类别在当日交易中的占比。
- 数值变换：计数与金额特征使用 `log1p`；类别特征为占比。
- 无交易时间步：全零，作为 null event 保留。
- 未使用字段：`age`、`gender` 和邮编字段暂不进入第一版，避免把静态属性与时序适配问题混在一起。

## 时间标签

- `t_onset`：客户第一笔 `fraud=1` 交易所在 step，只用于评估。
- `t_detect`：第一版可控实验定义为 `t_onset + 4`；20% 可检测阳性客户以固定随机种子模拟右删失。
- 阴性客户：`t_onset=-1`、`t_detect=-1`、`detected=False`。
- 接近数据末尾、`t_onset + 4` 超出 180 步的客户视为自然删失。

BankSim 本身没有“欺诈开始—平台确认”这对时间标注。因此，`t_detect` 是明确写入实验方案的模拟变量，不能表述成数据集原生真值。后续应改变延迟和删失率做敏感性实验。

## 数据划分与防泄漏

数据按客户分层划分为 70%/10%/20% 的训练、验证和测试集，分层条件是客户是否曾出现欺诈。同一客户不会跨集合。`fraud` 仅用于构造评估标签，不进入模型输入。

交易类别与欺诈的相关性较强。类别在交易发生时确实可见，因此可作为输入，但必须增加“移除类别占比”的消融实验，判断结果是否过度依赖场景标签。

## 复现命令

```powershell
python scripts/adapt_banksim.py `
  --source "<本地路径>\bs140513_032310.csv" `
  --output "<本地实验目录>" `
  --delay 4 `
  --censor-rate 0.2 `
  --seed 20261005
```

原始 CSV 和生成的 NPZ 暂不提交 Git 仓库。仓库仅保存适配代码、测试和不含个人本地路径的数据说明；待数据许可确认后再决定发布方式。
